# ADR 0003：监督者担任选主见证人

英文版：[English](../en/adr/0003-supervisor-witness.md)。

- 状态：已接受
- 日期：2026-10-10

## 背景

只有心跳、没有第三者时，主存储和从存储之间的网络一断，两边都可能认为自己该接写。订单系统要避免两个写入者。

监督者同时还负责拉起进程和按积压加减工人。它可以自然地持有「当前谁是主」这份名单。

## 决策

只有监督者能调用存储的提升接口。存储节点不因为对方心跳消失就自己升主。

订单进程和工人只使用监督者公布的主存储地址。写到旧代际时，存储返回 `epoch_fenced`，订单进程或工人刷新地址后再试一次。

切换开始时，监督者让网关暂停接受新单，上限 2 秒。新主公布后恢复。暂停期间新单得到 503。

监督者自身停止心跳或退出时，不改变现任主存储。已经在处理的下单继续完成。没有监督者的这段时间里，主存储如果也退出，系统停止接单，直到监督者回来再按规则提升。

## 后果

见证人只有一个。监督者和主存储先后失效时，可用性让位于「不要出现两个主」。这是第一版对分区的明确选择。

网关、订单副本、工人的拉起和伸缩跟选主在同一个进程里，实验时看一处状态页即可。

## 放弃的方案

- 存储节点互相选主。两节点无法在分区时形成多数，结果要么双主，要么都等待。
- 把见证人做成第三个存储副本并实现 Raft。那是另一项练习，不放进下单主线。
