# ADR 0004：Python 标准库与 sqlite

- 状态：已接受
- 日期：2026-10-10

## 背景

系统要跑在当前这台机器上，方便单步阅读超时、熔断、复制和故障注入。引入 Web 框架、ORM 或容器编排之后，演示故障时要先分辨是业务规则还是框架行为。

数据量是演示规模：令牌桶每秒约 10 个请求，任务积压上限 50。

## 决策

全部进程使用 Python 3 标准库。HTTP、JSON、并发和时间都不用第三方包。每个存储节点一个 sqlite 文件，由该进程用 SQL 访问。

复制在应用层按 `replication_log` 推送，不复制数据库文件，也不使用 sqlite 的集群方案。

进程由监督者直接拉起，第一版不写容器清单。

## 后果

依赖可在没有网络的环境里读完。机制都在自己的模块里：令牌桶、截止时间、熔断、退避、日志和故障文件。

标准库 HTTP 服务的连接处理足够支撑本机演示，不作为性能样本。

以后若要换成其他语言，对外契约仍以 OpenAPI 和本文档中的故障行为为准，不把 Python 类型泄漏给调用方。

## 放弃的方案

- 用现成的网关和数据库集群充当「分布式」。能跑起来，但超时、代际和任务领取都看不见。
- 第一版上 Kubernetes。副本、探针和扩缩容会变成集群配置，而不是这段代码里的规则。
